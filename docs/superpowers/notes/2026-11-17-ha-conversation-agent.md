## device_id / satellite_id for Voice PE

Plumbing is confirmed in source: `assist_satellite/entity.py:527` passes `satellite_id=self.entity_id`;
`assist_pipeline/run.py:181-189` stores `device_id` and `satellite_id`; `default_pipeline.py:~820-826`
passes both to `conversation.async_converse`. So they are populated when the request comes through an
`assist_satellite` entity (Voice PE via ESPHome). They are `None` for text typed in the Assist dialog or
via REST/websocket with no device. NOT verified live with real Voice PE hardware; treat as Optional and
verify during later integration testing.

## Chat log pattern (new in recent HA)

`ConversationEntity.async_process` already opens `async_get_chat_session` + `async_get_chat_log`, adds the
user text to the chat log, and calls `_async_handle_message(user_input, chat_log)`. Agents should override
`_async_handle_message`, not `async_process`. Conversation id is `chat_log.conversation_id`
(generated by the session when `user_input.conversation_id` is None).

`async_get_result_from_chat_log` requires the LAST chat-log item to be an `AssistantContent`, else it
raises HomeAssistantError. A text-only agent therefore appends assistant content itself with
`chat_log.async_add_assistant_content_without_tools(conversation.AssistantContent(agent_id=user_input.agent_id, content=text))`
(`chat_log.py:468-490`), then either calls `async_get_result_from_chat_log` or builds the result by hand.

Fallback: agents that do NOT use the chat log can still return a plain `ConversationResult`; the pipeline
adds assistant content itself if the last item is still the user turn (`default_pipeline.py:~833-840`).
Building the result by hand is the least coupled option.

## continue_conversation

- Field exists on `ConversationResult` (default False).
- `ChatLog.continue_conversation` (`chat_log.py:393-410`) auto-derives it: true when the last assistant
  message ends with `?`, `;` or full-width `？`. `async_get_result_from_chat_log` copies that.
- Pipeline: if result.continue_conversation, it records `continue_conversation_agent`
  (`default_pipeline.py:887-888`) and the satellite re-listens after the reply.
- So the brain's flag CAN be honoured: set `continue_conversation=` explicitly when building the result
  by hand. (The brief said the connector might ignore it; it need not.)

## Latency / timeout

No timeout is applied to the conversation step: `grep timeout` in `default_pipeline.py` shows only wake-word
timeouts, and `agent_manager.async_converse` has none. An agent can block as long as the brain takes (only
HTTP-client and satellite/ESPHome-side limits apply). Non-HomeAssistantError exceptions become an
`intent-failed` pipeline error (`default_pipeline.py:~846`); `HomeAssistantError` is caught in
`async_converse` and turned into an error IntentResponse (error text is spoken).
`ConversationBusyError` is raised if the same conversation_id is already being processed. The connector
should set its own HTTP timeout and raise HomeAssistantError (or return friendly speech) on failure.

```python
from typing import Literal
from homeassistant.components import conversation
from homeassistant.const import MATCH_ALL
from homeassistant.helpers import intent

class DestinyConversationEntity(conversation.ConversationEntity):
    _attr_supports_streaming = False

    @property
    def supported_languages(self) -> list[str] | Literal["*"]:
        return MATCH_ALL

    async def _async_handle_message(
        self,
        user_input: conversation.ConversationInput,
        chat_log: conversation.ChatLog,
    ) -> conversation.ConversationResult:
        # call brain with user_input.text, chat_log.conversation_id,
        # user_input.device_id, user_input.satellite_id, user_input.language
        reply_text, continue_flag = ..., False
        chat_log.async_add_assistant_content_without_tools(
            conversation.AssistantContent(agent_id=user_input.agent_id, content=reply_text)
        )
        response = intent.IntentResponse(language=user_input.language)
        response.async_set_speech(reply_text)
        return conversation.ConversationResult(
            response=response,
            conversation_id=chat_log.conversation_id,
            continue_conversation=continue_flag,
        )
```
